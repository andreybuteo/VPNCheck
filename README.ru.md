# VPN Check

[English version](README.md) · Языки интерфейса: русский, English, Deutsch, 中文, فارسی, العربية

Локальная утилита для Windows 11 x64: показывает доступность и задержки контрольных узлов
OpenAI/ChatGPT, Anthropic/Claude, Autodesk Fusion, Google, YouTube, Telegram, GitHub, Docker,
npm, PyPI, Hugging Face, Microsoft и Cloudflare через текущий VPN или явно заданный прокси.
Один файл `VPNCheck.exe`, без установки, без прав администратора, без облака и аккаунтов.

Программа проверяет **доступность контрольных узлов**, а не гарантирует работу приложений.
Доступность страницы YouTube не доказывает воспроизведение видео, доступность доменов Fusion —
сохранение проекта, TLS к API — успешный вызов модели. Ответ `401` означает «сервер ответил,
требуется авторизация», а не «API работает».

## Запуск и завершение

1. Подключите VPN.
2. Запустите `VPNCheck.exe` двойным щелчком. Backend слушает только `127.0.0.1` на свободном
   порту и открывает интерфейс в браузере по умолчанию. При открытии интерфейса никаких внешних
   запросов не выполняется.
3. Введите название профиля (например, «VPN — Германия»), проверьте маршрут в шапке и нажмите
   **«Начать проверку»**. Обычно проверка занимает несколько десятков секунд; при тайм-аутах —
   дольше. Кнопка **«Остановить»** прерывает активные пробы и не запускает новые.
4. Переключите VPN-сервер, дождитесь паузы между запусками (по умолчанию 60 с, меняется в настройках) и запустите проверку ещё раз.
   В разделе «История» отметьте два запуска и нажмите **«Сравнить выбранные»**.

**Закрытие вкладки не завершает программу.** Backend продолжает работать; повторный запуск
`VPNCheck.exe` не создаёт второй сервер, а открывает вкладку к уже работающему. Чтобы остановить
процесс и освободить порт, нажмите **«Завершить приложение»** (кнопка питания в шапке или внизу
панели настроек). Консольного окна у программы нет; если интерфейс закрыт и кнопка недоступна,
процесс `VPNCheck.exe` можно завершить в Диспетчере задач.

Параметры командной строки: `--no-browser` (не открывать браузер, URL печатается в консоль),
`--port N`, `--data-dir ПУТЬ`, `--version`, `--demo` (демо-режим для проверки интерфейса:
подставные результаты, без сетевых запросов, отдельный каталог данных; явно помечен в интерфейсе).

## Маршрут: системный (TUN) или прокси

- **Системный маршрут / TUN** — приложение идёт через текущую маршрутизацию Windows без прокси
  уровня приложения. Это не режим «обойти VPN». Если VPN работает как локальный прокси
  (например, v2rayN/xray на `127.0.0.1:10809`), а не как TUN-адаптер, в этом режиме трафик
  программы пойдёт напрямую, а браузер — через прокси: пути различаются, и шапка это покажет.
- **Прокси** — явно заданный HTTP CONNECT или SOCKS5 адрес `host:port` без авторизации. Для
  SOCKS5 имя разрешает прокси (удалённый DNS), локальный DNS-запрос к целевому домену не
  выполняется. При ошибке прокси программа **не** переключается на прямой маршрут. Прокси с
  логином/паролем не поддерживаются и отклоняются с объяснением; пароли не сохраняются.
- Настройки прокси Windows (WinINET) и переменные `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`
  читаются только как подсказка: обнаруженный адрес показывается в панели настроек, применить
  его можно одной кнопкой. PAC/WPAD в этой версии не поддерживаются.
- Семейство IP по умолчанию Auto; IPv4-only/IPv6-only доступны для системного маршрута как явно
  выбранный режим нового запуска. Фактически использованное семейство сохраняется в результате.
  За прокси семейство конечного сервера не наблюдается и помечается «не измерено через прокси».
- Опция «Показывать внешний IP» (по умолчанию выключена): один запрос к Cloudflare
  `https://www.cloudflare.com/cdn-cgi/trace` в начале и один в конце запуска через выбранный
  маршрут. Провайдеру передаётся ваш адрес. Страна — из ответа провайдера, ASN — нет данных.
  Изменение IP во время запуска отмечается предупреждением; одинаковый IP не доказывает, что
  маршрут не менялся.

## Что и как проверяется

Два типа контрольных точек:

- `tls` — DNS → TCP 443 → TLS с SNI и штатной проверкой сертификата, затем закрытие
  соединения. HTTP-запрос не отправляется. Используется для API, авторизации и CDN.
- `https` — один GET к небольшому документированному публичному ресурсу; DNS, TCP, TLS и TTFB
  измеряются на этом же запросе. Редиректы не выполняются, повторов нет, тело ограничено 64 КиБ.

Метрики: DNS, TCP, время прокси (CONNECT/SOCKS-рукопожатие), TLS, TTFB, «время до готовности TLS»
(от старта пробы до проверки сертификата — основная метрика для сравнения запусков) и общее
время. Неизмеренные значения показываются как «—» и экспортируются как `null`.

Режимы: **Быстрая** — одна проба каждого выбранного узла; **Стабильность** — до 5 узлов по 3
пробы с интервалом не менее 10 с, показываются min/median/max и размах. Размах — это разброс
задержки TLS/HTTP, а не сетевой jitter; доля неудачных проб — не потеря пакетов.

Щадящие лимиты backend: не более 4 проб одновременно и одна на хост, разнос стартов внутри
группы не менее 1 с, пауза между запусками (по умолчанию 60 с, в настройках «Проверка» → «Пауза перед повторной проверкой» от 10 до 1800 с; новое значение сразу применяется и к текущему ожиданию). Часовой лимит проб на хост отключён.
Остановка хоста после `403`/CAPTCHA действует до конца запуска, пауза
после `429` по `Retry-After` или 15 минут. Это осторожная настройка приложения, а не квота
сервисов; нулевой риск блокировки не обещается.

## Экран

На странице только главное: строка окружения с кнопкой «Применить маршрут», сводка из пяти плиток
(проверено, TLS подтверждён, ошибки, медиана, состояние запуска), строка состояния и карточки
сервисов. Карточка — название, задержка и одна строка: «2/2 доступны» или причина проблемы.
Нажатие на карточку открывает таблицу узлов с объяснением причины, советом и кнопкой
«Диагностика по двум маршрутам». Остальное свёрнуто и раскрывается по щелчку: «Что проверять»
(режим и группы), «Диагноз» (все вердикты), «Подробности запуска и отчёт», «История». Программа
помнит, какие разделы раскрыты. Во время проверки элементы страницы не сдвигаются: место под строку
состояния и под две строки причины в карточке занято заранее.

Цвет карточки всегда сопровождается значком и текстом: зелёный — все проверенные узлы группы доступны;
жёлтый — часть ответов отклонена/ограничена или медленно по локальному порогу; красный — только
ошибки; серый — не проверено. Порог «медленно» настраивается (по умолчанию 1500 мс по времени
до готовности TLS) и является локальной эвристикой, не SLA сервиса.

## Диагностика: почему сервис не открывается

- **Паспорт окружения** собирается при открытии интерфейса без сетевых запросов: запущенные
  VPN-клиенты (по процессам и слушающим портам), TUN-адаптеры и маршрут по умолчанию, split
  tunneling, локальные прокси, DNS адаптеров, прокси Windows и переменные окружения. По нему
  программа определяет режим (TUN / локальный прокси / без VPN) и предлагает маршрут одной кнопкой.
- **Вердикты** после каждого запуска: для каждой группы сервисов код причины, объяснение, улики и
  совет. Различаются гео-ограничение самого сервиса по стране выхода (например, `403
  unsupported_country` у OpenAI при работающем YouTube), CAPTCHA по репутации IP, подмена DNS,
  сброс соединения по SNI (DPI), тайм-аут (отбрасывание пакетов), перехват TLS, недоступный прокси,
  лимиты частоты, ошибки сервиса.
- **Кнопка «Диагностика по двум маршрутам»** в подробностях проблемной группы запускает её узлы по двум маршрутам: выбранному и
  альтернативному (локальный прокси VPN-клиента или, наоборот, системный маршрут). Так видно, идёт
  ли трафик программ мимо VPN. Действует та же пауза между запусками, что и для обычной проверки.
- **Группа «Россия напрямую»** проверяет раздельную маршрутизацию: российские сайты напрямую,
  остальное через VPN. После проб программа один раз открывает страницу Яндекс Интернетометра и
  сравнивает адрес, который видит Яндекс, с адресом выхода по Cloudflare через тот же маршрут.
  Если российские сайты идут напрямую, на карточке флаг России; если нет — карточка красная и
  показывает флаг страны, через которую они идут (страна адреса — по базе RIPEstat, RIPE NCC). Программа только
  наблюдает: маршруты, прокси и правила клиента VPN не меняются, поэтому проверка не может
  отключить VPN. Группа выбрана по умолчанию только при русском языке интерфейса.
- **«Сохранить отчёт JSON»** в разделе «Подробности запуска и отчёт» сохраняет полный диагностический отчёт: паспорт окружения,
  все пробы с этапами и таймингами, вердикты, глоссарий и инструкция `howToRead`. Файл можно
  отправить администратору или загрузить в LLM с вопросом «почему не открывается X». Чувствительные
  данные (внешний IP, адреса прокси, локальные адреса) включаются только по явному подтверждению.

Вердикты — эвристики без захвата пакетов и без прав администратора; у каждого указана уверенность.

## Замер скорости

Кнопка **«Скорость»** в шапке меряет канал через тот же маршрут, что и проверка (системный или
прокси VPN-клиента). Результат — в полосе «Скорость» под сводкой и в «История» → «Замеры скорости».

- **Cloudflare — ближайший узел** (по умолчанию): задержка (медиана 10 пустых запросов и разброс),
  скачивание и отдача. Узел выбирает сеть, обычно рядом с точкой выхода трафика, то есть с
  VPN-сервером; его код (FRA, AMS…) показывается рядом с результатом. Используются те же адреса,
  что у страницы speed.cloudflare.com (`/__down`, `/__up`).
- **Hetzner — Фалькенштейн или Хельсинки**: неподвижная точка с известным городом, только скачивание
  тестового файла частями (`Range`). Задержку и отдачу там не измерить.

Как программа бережёт серверы (чтобы ни вас, ни VPN-адрес не заблокировали):

- только по нажатию кнопки, никаких фоновых и повторных замеров, повторов после ошибки нет;
- 8 с на этап, 4 соединения HTTP/1.1, около 150 МБ скачивания и 50 МБ отдачи за замер (запросы, уже
  бывшие в пути, могут добавить несколько МБ) — меньше, чем делает сама страница Cloudflare; на быстром
  канале этап кончается раньше 8 с, как только набран потолок;
- пауза 3 мин между замерами и не больше 20 замеров за сутки (сохраняется при перезапуске);
- замер и проверка сервисов не идут одновременно;
- честное имя клиента `VPNCheck/<версия> (speed test, one run on user request)`, без маскировки под браузер;
- при ответе 429, 403 или проверке «человек ли вы» (`cf-mitigated: challenge`) замер сразу
  прекращается, а сервер откладывается на время из `Retry-After` или на час; остальные серверы
  остаются доступны.

Перед замером под кнопкой появляется подсказка с сервером, маршрутом и трафиком (до ~200 МБ); её
можно отключить галочкой «Больше не спрашивать». Во время этапа в плитке летит светящаяся точка и
рисует скорость, после этапа остаётся след с выводом «ровно», «колеблется» или «с провалами». Мбит/с считаются по
переданным байтам после разгона (первые 1,5 с не учитываются). Цифры близки к speedtest.net, но не
совпадут: там другой сервер. Через прокси VPN-клиента задержка включает и сам прокси.

## IP выхода — последние 10

Полоса «IP выхода» под замером скорости всегда на виду: последние 10 проверок и замеров слева
направо, от старых к новым. В каждой ячейке флаг страны выхода, адрес, время и что это было (проверка или скорость).
Флаги упрощённые и нарисованы в самой программе (Windows не показывает флаги-эмодзи); для стран вне
набора — значок с кодом. Одинаковые адреса окрашены одинаково, поэтому чередование видно сразу: сегодня один
адрес, завтра другой, потом снова первый. Последняя запись обведена, при наведении — маршрут,
профиль и предыдущий адрес.

- Цветов четыре (синий, жёлтый, розовый, зелёный): на тёмном и светлом фоне больше ни один не
  остаётся отличимым от всех остальных (проверено расчётом). Пятый и следующие разные адреса —
  серые с пометкой «другой»; сам адрес всегда написан текстом.
- Адрес узнаётся одним коротким запросом к Cloudflare (`cdn-cgi/trace`) через выбранный маршрут:
  в начале и в конце проверки и перед замером скорости. Если за время проверки адрес сменился,
  в ячейке пометка «менялся».
- Журнал включён по умолчанию; выключается в настройках («Журнал IP выхода»). Тогда запросов IP
  нет. В экспорте и кратком итоге адреса по-прежнему скрыты, пока не включены подробные данные.

## Добавление адресов

Панель настроек → «Реестр контрольных точек». Встроенные точки можно включать и выключать;
их адреса зафиксированы. Свои точки — только публичные HTTPS-хосты на порту 443, без логина и
пароля в URL; частные, loopback, link-local и служебные адреса отклоняются как в реестре, так и
повторно перед подключением после разрешения имени (защита от DNS rebinding). Реестр можно
экспортировать и импортировать как JSON; импорт полностью проверяется, при ошибке прежняя
конфигурация сохраняется. Источники и даты проверки каждой встроенной точки: `docs/REGISTRY.md`.

## Хранение и экспорт данных

Каталог `%LOCALAPPDATA%\VPNCheck`:

- `settings.json` — настройки без секретов;
- `registry.json` — реестр (после первого изменения);
- `limiter.json` — состояние лимитов (cooldown, потолки, паузы после 429);
- `history\` — по файлу на запуск, последние 100 запусков, плюс `index.json`;
- `vpncheck.log` — журнал без cookies, токенов и тел ответов.

Запись атомарная; повреждённый файл переносится в копию `*.corrupt-*` и не уничтожает историю.
Последние результаты доступны без интернета.

Экспорт из истории: **JSON** (версионированная схема, `schemaVersion: 1`), **CSV** (UTF-8 с BOM,
разделитель `;`, одна строка на пробу, защита от formula injection), **«Копировать итог»** —
короткий текст для администратора. Внешние IP, адреса прокси, peer в режиме прокси и
query-параметры своих URL по умолчанию скрыты; флажок «Включать внешний IP и адреса прокси»
включает их явно.

## Языки

Все шесть языков интерфейса встроены в exe. Язык выбирается по браузеру и Windows и меняется
переключателем в шапке; вердикты, ошибки и экспорт пишутся на выбранном языке. Переводы лежат в
`internal/i18n/locales/<код>.json` (русский исходный текст → перевод). Исходные строки собирает
`go run ./tools/i18nkeys` в `internal/i18n/keys.json`; `go test ./internal/i18n` падает, если в
каком-то языке не хватает строки или потеряна подстановка `%s`/`%d`.

## Сборка из исходников

Нужен Go 1.27 (`winget install GoLang.Go`). В папке проекта:

```powershell
.\build.ps1
```

Скрипт выполняет `go vet`, `go test`, собирает `dist\VPNCheck.exe` (`-trimpath -ldflags "-s -w
-H windowsgui"`, без CGO и упаковщиков), печатает размер и SHA-256 и создаёт ZIP. Бинарник не
подписан кодовой подписью: SmartScreen может предупредить; не отключайте защиту Windows,
сверьте SHA-256 из `VPNCheck.exe.sha256`.

Отчёт о выполненных тестах и фактических измерениях сборки: `docs/BUILD_REPORT.md`.

## Версионирование

Номер версии задаётся в `internal/app/app.go` (`Version`) и дублируется в `winres/winres.json`
(сведения о версии exe). Правило: **большое изменение — +1.0, любое другое — +0.1**. Текущая версия
показывается в шапке интерфейса, в свойствах `VPNCheck.exe` (вкладка «Подробно») и в `--version`.
История изменений: `CHANGELOG.md`.

## Ограничения методики

- Проверяются контрольные узлы, а не полный сценарий работы приложений; Telegram Web/Bot API не
  заменяют MTProto-клиент, Autodesk Platform Services — все компоненты Fusion.
- Лимит тела 64 КиБ — ограничение приложения, а не гарантия того же числа байт на проводе.
- ICMP, traceroute, HTTP/3, MTU и WebSocket в эту версию не входят.
- Результаты зависят от момента запуска, split tunneling и текущего состояния сервисов; для
  сравнения VPN-профилей запускайте проверку в одинаковых условиях и смотрите на маршрут.

## Структура проекта

```
cmd/vpncheck/      точка входа, ресурсы Windows (значок, версия)
internal/          движок проб, guard, ограничитель, классификация, реестр, хранилище, отчёты, API, сервер
web/               интерфейс (HTML/CSS/JS, favicon), встраивается в exe
winres/            исходники ресурсов Windows; tools/mkicon — генератор значка
docs/              SPEC.md (исходное ТЗ), PLAN.md (рабочий план), REGISTRY.md, BUILD_REPORT.md
tools/             mkicon — генератор значка, i18nkeys — сбор строк для перевода
build.ps1          сборка, тесты, ZIP; результат в dist/ (не в git)
```
