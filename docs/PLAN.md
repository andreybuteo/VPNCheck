# VPN Check — рабочий план

Исходное ТЗ: `docs/SPEC.md`. Среда: Windows 11 Home x64, Go 1.27.0 (winget), PowerShell 7.6, Chrome по умолчанию.
Наблюдение среды: на машине разработчика VPN работает как локальный HTTP-прокси `127.0.0.1:10809`
(WinINET + переменные `HTTP_PROXY/HTTPS_PROXY`), TUN-адаптера нет. Это живой сценарий для режима «Прокси»
и для предупреждения «путь браузера и программы различаются».

## Структура модуля

```
go.mod                      module vpncheck, go 1.27, без внешних зависимостей (цель)
cmd/vpncheck/main.go        запуск: единственный экземпляр, сервер на 127.0.0.1:0, открытие браузера, ожидание quit
internal/
  app/                      версия, пути %LOCALAPPDATA%\VPNCheck, общие константы лимитов
  registry/                 модель endpoint, встроенный реестр (JSON), валидация, импорт/экспорт
  guard/                    проверка целевых адресов: loopback/private/link-local/multicast/metadata, пост-DNS, anti-rebinding
  probe/                    сетевой движок: tls-проба, https-проба (httptrace), дайлер, HTTP CONNECT, SOCKS5, тайминги
  limiter/                  4 глобально / 1 на host / 1 с внутри группы, cooldown 60 с, 12 проб/час на host, блок 403/429, персист
  classify/                 транспорт + HTTP → итоговая подпись, агрегат группы, порог «медленно»
  runner/                   оркестрация запуска: очередь, режимы Быстрая/Стабильность, прогресс, отмена, внешний IP
  store/                    settings.json, history.json (100 запусков), limiter-state.json, атомарная запись, повреждённый JSON
  report/                   сравнение двух запусков, экспорт JSON (schema v1), CSV (BOM, защита от формул), краткий итог
  sysproxy/                 чтение WinINET (реестр) и переменных окружения только для подсказки
  server/                   HTTP API, cookie-сессия, Host/Origin/Sec-Fetch-Site, CSRF-заголовок, SSE, embed UI
web/                        index.html, app.css, app.js, icons.svg — встраиваются через go:embed
build.ps1, README.md
```

## Фазы

1. **Скелет и безопасность локального API.** go.mod, main, сервер на свободном порту 127.0.0.1, токен сессии
   через одноразовый URL → HttpOnly cookie SameSite=Strict, проверка Host/Origin, CSRF-заголовок для изменяющих
   операций, SSE-канал, `POST /api/quit`, открытие браузера, единственный экземпляр (второй запуск открывает
   вкладку к уже работающему). Заглушка UI. Тесты: Host/Origin/CSRF/отказ чужому Origin.
2. **Хранилище.** Пути, атомарная запись (tmp + rename), settings/history/limiter-state, лимит 100 запусков,
   повреждённый файл → резервная копия и пустое состояние без потери остального. Тесты.
3. **Реестр сервисов.** Схема endpoint (id, group, role, host/url, kind tls/https, expected statuses, enabled,
   source, verifiedAt). Встроенный реестр 25–35 точек: проверка назначения по официальным источникам через
   WebFetch, ссылка и дата в профиле; неподтверждённые точки выключены с причиной. Валидация импорта,
   пользовательские точки только https:443 без credentials. Тесты валидации.
4. **Сетевой движок.** Guard адресов с проверкой на этапе Control перед connect (закрывает rebinding).
   Дайлер с корректным учётом Happy Eyeballs (TCP = от первой попытки до успешной, не сумма). tls-проба:
   DNS → TCP → TLS(SNI, штатная проверка) → close. https-проба: один GET с httptrace, без редиректов,
   тело ≤ 64 КиБ, лимиты заголовков, DisableKeepAlives, свежий Transport на пробу. Тайм-ауты 10/4/4 с.
   HTTP CONNECT и SOCKS5 (RFC 1928, доменное имя → удалённый DNS) собственной реализацией, время CONNECT
   отдельно от TLS, ненаблюдаемые метрики → null («не измерено через прокси»). Без скрытого fallback на прямой маршрут.
   Тесты: локальный TLS-сервер с тестовым CA, локальный тестовый HTTP-CONNECT и SOCKS5 прокси, зависшее тело,
   медленный прокси, отмена, разрешение loopback только через test-only hook.
5. **Ограничитель.** Семафор 4 / 1 на host / разнос 1 с в группе, один активный запуск, cooldown 60 с от старта
   предыдущего, скользящее окно 12/час на host с персистом, стоп host при 403/CAPTCHA до конца запуска,
   429 → Retry-After (секунды и дата) / известные reset-заголовки / минимум 15 мин, персист, не сбрасывается
   при смене профиля. Тесты со сдвигаемыми часами.
6. **Классификация.** Таблица из раздела 8 ТЗ, раздельные transport/http результаты, агрегат группы
   («2/3 доступны, 1 отклонён»), порог «медленно» настраиваемый по одной метрике. Тесты на 200/301/401/403/404/405/429/500
   и DNS/TCP/TLS ошибки.
7. **Оркестратор запуска.** Быстрая: одна проба на включённый endpoint, прогресс по завершению. Стабильность:
   до 5 узлов × 3 пробы, интервал ≥ 10 с на узел, min/median/max, успехи, размах, метка малой выборки.
   Семейство IP Auto/IPv4/IPv6 с сохранением реального. Опция внешнего IP выкл. по умолчанию: один запрос в начале
   и в конце через тот же маршрут, провайдер и факт передачи показываются. Отмена закрывает активное, не стартует новое.
   Тесты с фейковым пробером.
8. **Отчёты.** Сравнение по стабильным id и совпадающим параметрам, «было → стало», абсолютная и процентная
   разница только при двух измеренных значениях и ненулевой базе, предупреждение о несопоставимости.
   JSON schema v1 с null для неизвестного, CSV UTF-8 BOM одна строка на пробу и экранирование `= + - @ \t \r`,
   краткий текстовый итог без IP/прокси/секретов; подробные данные — явный выбор. Тесты.
9. **Интерфейс.** Русский dashboard: тёмная графитовая тема по умолчанию, светлая переключателем, бирюзовый акцент,
   системный шрифт, табличные цифры. Шапка (профиль, режим маршрута, Начать/Остановить), переключатель
   Быстрая/Стабильность, выбор сервисов, сводка со знаменателями, сетка карточек, раскрывающаяся таблица
   деталей, поиск и фильтры, история и сравнение, экспорт, копирование итога, боковая панель настроек
   (маршрут, прокси с подсказкой из системы, реестр, порог, внешний IP), кнопка «Завершить приложение».
   Состояния: первый запуск, нет интернета, все ошибки, частичный, отмена, cooldown, повреждённые настройки.
   Клавиатура и видимый фокус. Проверка во встроенном браузере на 1366×768 и узком экране, обе темы.
10. **Сборка и выдача.** `go test ./...`, `go vet ./...`, `go test -race` (требует CGO/gcc; если недоступен —
    честно указать). `build.ps1` с `-trimpath -ldflags "-s -w -H windowsgui"`, `VPNCheck.exe`, ZIP, SHA-256,
    фактический размер и память в простое. Минимальный smoke-test реальной сети через собственный ограничитель
    приложения — только с согласия пользователя. `README.md` на русском. Краткий отчёт о тестах.

## Принятые решения

- Только стандартная библиотека Go; SOCKS5 и CONNECT реализуются вручную ради раздельных таймингов.
- Тайминги для прокси-режима берутся из собственного дайлера (TCP до прокси, CONNECT/SOCKS-handshake), из
  httptrace — TLS и TTFB. В прямом режиме DNS/TCP/TLS/TTFB из httptrace.
- Сессия: cookie HttpOnly SameSite=Strict + заголовок `X-VPNCheck-CSRF` для POST/PUT/DELETE; SSE защищён
  cookie и проверкой Host/Origin/Sec-Fetch-Site. Никаких CORS-заголовков.
- Бинарник собирается с `-H windowsgui`: без консольного окна; завершение — кнопкой в UI. Второй запуск
  exe не создаёт второй сервер, а открывает вкладку к работающему.
- Реестр: API/авторизация/CDN — `tls`; `https` только для документированных небольших ресурсов
  (`/.well-known/openid-configuration`, `/v2/` Docker Registry с ожидаемым 401, `/-/ping` npm и т.п.).
- Данные: `%LOCALAPPDATA%\VPNCheck\{settings.json, history.json, limiter.json, registry.json}`.
